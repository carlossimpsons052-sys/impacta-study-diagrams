Conceitos Básicos de Virtualização

Histórico

Virtualização e Máquinas Virtuais

Antes dos containers, o modelo dominante era o das Máquinas Virtuais (VMs), tecnologia que surgiu durante a década de 1960 com a IBM. Uma VM roda em cima de um componente chamado hypervisor, que faz a mediação entre o hardware físico e os sistemas operacionais convidados. Exemplos clássicos de hypervisor: VMware e VirtualBox.

Tipo 1 — Bare Metal

Executa diretamente sobre o hardware, sem sistema operacional intermediário. Oferece alto desempenho, controle e isolamento. Exige maior custo. Ex: VMware ESXi, Hyper-V.

Tipo 2 — Hosted

Executa sobre um sistema operacional host. Menor desempenho, mas muito mais flexível e fácil de usar. Ex: VirtualBox, VMware Workstation.

Critério Bare Metal (Servidor Físico) Virtualização (VM)
Desempenho Alto — recursos dedicados Compartilhado entre VMs
Isolamento Máximo — sem compartilhamento Bom, por hypervisor
Custo Alto Reduzido via compartilhamento
Ferramentas Cloud — AWS EC2, Azure VM, Google Compute

Componentes do Linux (e de qualquer SO)

Entender Linux é fundamental porque os containers nasceram como uma tecnologia primariamente Linux. Os principais componentes de um sistema operacional são:

Kernel

Núcleo do sistema operacional. Gerencia os recursos do hardware.

Shell

Interpretador de linha de comando. Interface entre usuário e SO.

Sistema de arquivos

Organiza e armazena arquivos em estrutura hierárquica de diretórios.

Bibliotecas

Coleção de código pré-escrito. Fornece funções para o desenvolvimento.

Serviços e Daemons

Processos em segundo plano executados automaticamente pelo sistema.

Gerenciador de pacotes

Ferramenta para instalar, atualizar e remover software (apt, yum, dnf).

12:35 — Container

O que é um Container?

Atenção: o container não carrega todos os módulos do S.O. Linux como uma VM faz. Ele contém apenas os componentes necessários para rodar a aplicação.

Um container é uma tecnologia que permite executar aplicativos de forma isolada usando recursos do kernel Linux — especificamente namespaces (para isolamento) e cgroups (para controle de recursos). Vários containers compartilham o mesmo kernel do host, mas têm seus próprios sistemas de arquivos, processos e rede.

A tecnologia de containers tem raízes no chroot (1979), evoluiu com os cgroups introduzidos no kernel Linux em 2006, e foi popularizada mundialmente pelo Docker em 2013.

Critério VM Container
Kernel Próprio (SO completo) Compartilha o do host
Tamanho Gigabytes Megabytes
Inicialização Minutos Segundos
Isolamento Forte (hypervisor) Via namespaces/cgroups
Portabilidade Pesada (transferência lenta) Leve e rápida
A VM, como carrega todas essas aplicações, todos esses componentes, acaba sendo tanto pesada para transferir de um servidor para outro, quanto para inicializar e parar. — Prof. Daniel

As vantagens do container incluem: implantação automatizada (DevSecOps), isolamento de falhas em cascata, redução de espaço em disco, agilidade, elasticidade, melhoria na governança e inicialização muito mais rápida.

20:24 — Docker

Por que o Docker nasceu?

A origem do Docker é prática: imagine um desenvolvedor que entrega um pacote que não funciona em produção. Ele argumenta que na própria máquina tudo estava funcionando. A solução seria levar a máquina inteira para a produção — e assim nasceu o Docker. Ele garante que o comportamento da aplicação em dev, homologação e produção seja idêntico, eliminando o esforço de comparação entre ambientes.

Docker

Plataforma open source para construir, gerenciar e executar containers. A mais popular do mercado.

Podman

Alternativa open source. Roda sem daemon e sem privilégios de root. Compatível com Linux, Windows e Mac.

Containerd

Gerencia o ciclo de vida dos containers desde o download da imagem até a execução e supervisão.

O Docker deve ser evitado quando: o SO completo for necessário, para aplicações monolíticas, hardware específico ou necessidades especiais. Para projetos profissionais, o ideal é um serviço por container — vários serviços no mesmo container levam a conflitos e dificuldade de gerenciamento.

Instalação do Docker

Existem diversas formas de instalar o Docker. As principais são: Docker Engine, Docker Desktop, Docker Toolbox e via gerenciador de pacote do sistema operacional.

É muito importante, antes de a gente sair fazendo, que a gente faça uma pesquisa e entenda as principais opções do mercado. — Prof. Daniel

Docker Desktop

Disponível para Windows, MacOS e Linux. Inclui Docker CLI, Docker Compose, Docker Daemon e Kubernetes. Requer: virtualização habilitada na BIOS + Hyper-V + Containers Windows features.

Docker Engine via Script (Ubuntu)

Instalação via Convenient Script. O mais comum em ambientes Linux/servidor.

Docker Toolbox

Alternativa para sistemas mais antigos que não suportam Docker Desktop. Inclui Docker Machine e VirtualBox. Considerada obsoleta.

Instalação por SO

Linux: via apt, yum ou dnf

MacOS: via Homebrew — brew install docker

Windows: via Chocolatey — choco install docker

Docker Community vs Enterprise

Community: open-source para desenvolvedores.

Enterprise: pago, robusto para empresas. Inclui suporte técnico, segurança avançada, certificação para produção e orquestração integrada.

Script de Instalação — Ubuntu
# Convenient Script — baixa e executa o instalador do Docker curl -fsSL https://get.docker.com -o get-docker.sh sudo sh ./get-docker.sh --dry-run
# Instalação manual via apt (Ubuntu) sudo add-apt-repository "deb [arch=amd64] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" sudo apt update sudo apt install docker-ce sudo systemctl status docker # Adicionar usuário ao grupo Docker (para executar sem sudo) sudo usermod -aG docker $USER # Sair da sessão e entrar em uma nova docker run hello-world

Adicionar o usuário ao grupo Docker é necessário para executar os comandos sem ficar pedindo permissão a cada vez.

08:25 — Container e Imagem

Container e Imagem: a diferença fundamental

Um container funciona como um micro-VM rodando no sistema operacional dentro do host. Cada componente — backend, frontend, banco — executa em seu próprio processo isolado, completamente separado de tudo mais na máquina. No Docker, o container é uma forma de virtualização leve que cria um ambiente isolado para executar aplicações, compartilhando o kernel do host.

A imagem Docker é um pacote padronizado que inclui todos os arquivos binários, bibliotecas e configurações necessárias para criar um container. Ela é construída a partir de um arquivo chamado Dockerfile, que define as instruções para sua criação. Isso garante que a aplicação funcione de maneira consistente em qualquer ambiente.

Oficiais

Imagens mantidas pela própria empresa dona do software. Máxima confiabilidade.

Selos (Verified)

Publicadas por editores verificados pelo Docker. Alta confiabilidade.

Open Source

Patrocinadas pela Docker. Código aberto e auditável.

Docker Hub

É o registro público padrão. O comando docker procura imagens aqui por padrão. Usuários podem deixar imagens privadas. Empresas podem criar registries privados (GitHub, Azure, AWS Elastic Registry, Google).

Criando o Primeiro Container

Para criar e executar o primeiro container, o comando principal é o docker run. Se a imagem não existir localmente, o Docker busca automaticamente no Docker Hub e faz o download.

# Comando básico — cria e executa um container hello-world docker run hello-world
# Parâmetros adicionais para definir o container com mais controle # --name: nome do container | -p: mapeamento de porta | -d: modo background | nginx: imagem docker run --name meu-nginx -p 8080:80 -d nginx
# Lab 03 — Listar todos os containers (-a = all, incluindo parados) docker container ls -a
É sempre importante você definir explicitamente o nome que você quer dar para o seu container. — Prof. Daniel
Parâmetros do docker run
--name
Define o nome do container. Facilita referenciá-lo depois.
-p [externa:interna]
Mapeia porta do host para porta do container. Ex: -p 8080:80
-d
Detach — executa em modo background (não trava o terminal).
nginx (imagem)
Nome da imagem a usar. Sem versão explícita usa a tag latest.

Dockerfile e Imagens

Até a Parte 3, o professor trabalhou com imagens prontas disponíveis no Docker Hub. A partir daqui, o objetivo é criar suas próprias imagens usando o Dockerfile — um script que contém um conjunto de instruções definindo como a imagem deve ser construída.

Atenção de segurança: deve-se evitar dados sensíveis como senhas ou chaves diretamente no Dockerfile. Além disso, cada instrução cria uma nova camada na imagem — camadas otimizadas ajudam a reduzir o tamanho final.
Instruções Dockerfile
Instrução Função
FROM Define a imagem base (ex: ubuntu, node, python:3.9-slim)
COPY / ADD Copia arquivos do host para dentro do container
RUN Executa comandos durante a construção da imagem
CMD / ENTRYPOINT Define o comando principal a executar quando o container iniciar
EXPOSE Indica quais portas o container usará
WORKDIR Define o diretório de trabalho dentro do container
Exemplo — Python
# Use uma imagem base do Python FROM python:3.9-slim # Defina o diretório de trabalho no container WORKDIR /app # Copie os arquivos necessários para o diretório COPY . /app # Instale as dependências RUN pip install -r requirements.txt # Comando para rodar a aplicação CMD ["python", "python2.py"]
Exemplo — Java
# Define a imagem base do OpenJDK FROM openjdk:17-jdk-slim # Define um diretório de trabalho dentro do contêiner WORKDIR /app # Copia o arquivo JAR da aplicação para o contêiner COPY target/minha-aplicacao.jar /app/minha-aplicacao.jar # Expõe a porta 8000 EXPOSE 8000 # Define o comando de execução da aplicação CMD ["java", "-jar", "/app/minha-aplicacao.jar"]

Para minimizar o tamanho da imagem: use imagens base leves como Alpine, remova dependências desnecessárias, e coloque as instruções que mudam com menos frequência no início do Dockerfile para aproveitar o cache de construção.

Glossário
Registry (Registro)
Local centralizado que armazena e gerencia imagens de um mesmo container. O mais conhecido é o Docker Hub.
Repository (Repositório)
Coleção de versões de imagens de container relacionadas dentro de um registry. É como um "projeto" dentro do Docker Hub.
.ISO
Imagem de disco que contém uma cópia exata do sistema de arquivo de uma VM. Funciona como um "snapshot" de uma máquina em execução, usado para distribuir sistemas operacionais e aplicações instaladas.
